# 设置有效性修复与自动应用验收

日期：2026-09-10。基于 `beta` 分支的设置有效性调研，面向 Android / arm64。以下为实现后的状态，原始问题分析保留在 [调研报告](settings-effectiveness-audit.md)。

## 已实施

| 原问题 | 修改与确认方式 |
| --- | --- |
| DNS 劫持为无效开关 | 改为“自动接管”只读说明。兼容旧字段，但不作为 VPN 差异或行为依据。 |
| 路由地址未传入 Android | 共用配置到 `VpnOptions.routeAddress` 的转换；Flutter 提交前和原生创建前校验 CIDR，删除异常降级全局路由。 |
| allow-lan 热更新遗漏 | Go 双向写入 AllowLan 并刷新监听；额外核对真实监听端口，绑定失败返回事务。 |
| 规则参数回调为空 | noResolve/src 写回草稿模型；保留保存操作，保存后提交数据库并进入自动应用队列；失败按规则修订回退。 |
| DNS 来源和编辑有效性不明确 | 与实际配置合成共用来源判断，区分订阅、APP 覆写、自动补全；订阅 DNS 时只显示禁用预设。 |
| 三处 IPv6 易混淆 | 保留 VPN 接管、内核能力、DNS AAAA 三种偏好；说明 DNS 受基础 IPv6 限制，基础开关完整重载。 |
| 访问控制过滤删除选择 | 过滤仅影响列表，保存保留隐藏勾选；两种模式均显示隐藏已选数量。 |
| 保存与应用脱节 | 配置热更新、完整合成与 VPN 重建统一串行；重载/重建按最后一次有效修改防抖 1 秒，后续热更新并入批次。 |
| 错误仍可能显示成功 | 候选校验、内核响应和原生会话确认共同决定结果；无效 DNS 监听地址与端口绑定失败均返回错误。 |

## 事务与边界

- 共用现有运行配置提交闸门。保存冻结的配置、运行 YAML、编辑修订和订阅身份，自动设置与普通订阅刷新不会竞争写文件。
- 应用中的新修改独立保留，包含“改走又改回同值”的情况。旧结果只能确认当时实际应用的配置，不能覆盖新偏好。
- 失败恢复仍属于失败修订的设置及持久化值，运行配置和原生参数最多恢复一次；恢复失败保留故障与重试入口。
- 显式停止、智能暂停优先。停止/暂停时仅保存，启动/恢复时才应用。启动已确认的编辑不会再次触发重复重载。
- 按用户真机反馈，删除页面顶部常驻状态行：成功/等待下次生效/短暂重连使用原有通知提示；失败复用“关于”页项目/内核弹窗的 CommonDialog、内容框和 SurgeDialogActionRow，提供“关闭 / 重试”。没有修改前确认框。
- Profile/debug 的既有 Phase 4 通道增加 `settings_probe` 有限字段测试命令，直接调用与 UI 相同的 Provider。生产包不注册该通道；不接受任意配置、代码或订阅内容。

## 真机证据

设备为小米 Android 手机（model `25042PN24C`），测试包 `com.slclash.app.profile`，用 `adb install -r` 覆盖。未覆盖日用包，也未更改原有内核统计源码。

| 验证项 | 观察结果 |
| --- | --- |
| 局域网访问 | allow-lan 开启后，电脑 TCP 成功连接手机 7890；关闭并确认应用后，同一连接超时。两方向均未重建 VPN。 |
| 自定义实际路由 | 设置 `10.0.0.0/8` 后，Android `dumpsys connectivity` 中 profile VPN 的 tun0 路由出现该 CIDR，未出现全局 IPv4 默认路由；不以 YAML 代替原生证据。 |
| 协议栈与连续编辑 | mixed→gvisor，并连续修改基础/DNS IPv6；日志最后一次 pending 为 150812ms，applying 为 151814ms，仅一次重建，152339ms 确认成功，会话 ID 保持。system 栈也通过显式启动应用。 |
| 应用中新修改 | 恢复原设置过程中再次修改端口，新设置保留并在上一批结束后进入下一批；未覆盖。 |
| 真实失败回退 | 用临时 ADB reverse 占用 7899，修改 mixed-port 后收到真实监听失败；恢复 7890，原生仍 RUNNING、会话 ID 不变。重复测试的运行 YAML SHA-256 保持 `ec8af1d03b7b4cf70f2f8977a81af986719864a55c33ce5233fae0daba448338`。测试后移除 reverse。 |
| 显式停止优先 | 修改栈模式后立即停止，未执行待重建；超过 13 秒后仍 STOPPED，设置状态 deferred，后续仅显式启动才生效。 |
| 智能暂停 | 可信网络策略触发原生 PAUSED 后修改 DNS IPv6，仍为 PAUSED 且状态 deferred，没有自动恢复。随后显式恢复。 |
| 可视化 | 已看到 DNS 劫持只读说明、订阅 DNS 来源与下级置灰、三个 IPv6 的说明。根据用户反馈去除常驻状态行；最终失败弹窗使用“关于”页同一套组件，真机显示“关闭 / 重试恢复”，点击重试后 122139ms applying → 122477ms applied，保持 RUNNING。 |

端口错误及原生路由来自真实设备，恢复失败和订阅切换竞态等难稳定复现的分支另由协调器测试覆盖，二者不混记。原始采样日志在本地 `.dev-tools/settings-device-evidence.log`，不提交订阅、节点或完整手机日志。
